# Offroad Racing 4x4 (React Native)

The classic 2D hill-climb from `../src/game` (Phaser), rebuilt as a native React Native app with
**100 levels, 100 vehicles, 10 environments and 17 kinds of obstacle**. It is played in landscape only.

- **Expo SDK 58 / React Native 0.88**, TypeScript.
- **Physics:** `matter-js`, with the vehicle model, terrain formula, fuel, stunt and scoring rules ported
  from the original game so the car drives the same.
- **Rendering:** `@shopify/react-native-skia`. Everything is drawn in code; there are no image files.
- **Ads:** Google AdMob (banner, interstitial, rewarded) through `react-native-google-mobile-ads`. Setup,
  placements and frequency rules are in [docs/ADMOB.md](docs/ADMOB.md); IDs go in `.env` (see `.env.example`).
- **Saves:** AsyncStorage. **Sound:** `expo-audio`, playing WAV files generated by `scripts/gen-audio.mjs`.

The Vite + Capacitor app in the repository root (3D expedition and the original Phaser 2D mode) is untouched.

## Run it

```bash
cd mobile
npm install
npm run web        # browser build, http://localhost:8081  (arrow keys / WASD drive, P pauses)
npm run android    # builds and installs a development build (needs Android Studio / a device)
npm run ios        # same for iOS (needs a Mac with Xcode)
```

**Expo Go** (`npm start`, then scan the QR code) runs the game **without ads**: Expo Go cannot contain the
AdMob native code, so the ads layer switches itself off there. To see ads you need a build of this app
(`npm run android`, or EAS Build).
`npx expo prebuild` generates the `android/` and `ios/` folders (they are not committed).

## Check it

```bash
npm run typecheck          # tsc
npm test                   # 46 tests: levels, cars, terrain, pickups, save rules, physics, stunts, ad rules and rewards
npm run bot                # automated driver plays all 100 levels
npm run bot -- cars        # every one of the 100 cars finishes levels 1 and 20
npm run bot -- starter     # how far the stock starter jeep gets (all 100)

npx tsx scripts/diag.ts 1 100 mountain-jeep   # time lost and deaths per obstacle type

```

### Building an APK

```bash
eas build --platform android --profile preview    # cloud build, installable APK
```

Release builds are made **without R8 code shrinking** (`app.config.js`). Expo turns shrinking on by default, and
the first APK crashed at launch because of it: R8 removed a database class that the Google Mobile Ads SDK's
WorkManager creates by name (`Failed to create an instance of androidx.work.impl.WorkDatabase`). Keep rules
for it are in `app.config.js` too, so shrinking can be tried again with `ANDROID_MINIFY=1`; test that build on
a phone before shipping it.

The build is also set up to use less memory on the build machine (`app.config.js`): only the two phone CPU
types are compiled (arm64-v8a, armeabi-v7a), Gradle gets a 4 GB heap and at most two workers. Without this,
cloud builds sometimes died with "Gradle build daemon disappeared unexpectedly". An APK built this way does
not run in an x86 emulator; set `ANDROID_ALL_ARCHS=1` for one that does.

**Frame rate.** Expo Go runs the JavaScript in development mode, which is several times slower than a
release build. For a realistic number in Expo Go start the server with `npx expo start --no-dev --minify`,
or measure in the APK (Settings -> Show frame rate).

## What is in the game

| | |
|---|---|
| Levels | 100, in 10 environments of 10 stages: Green Valley, Pine Forest, Desert Storm, Rocky Mountains, Snow Mountain, Jungle Expedition, Mud Marsh, Neon City, Red Canyon, Volcanic Wasteland. 0.8 km to 4.2 km. A level unlocks when the one before it is finished. |
| Vehicles | 100 = 10 body styles (jeep, van, pickup, SUV, buggy, monster truck, hatchback, muscle car, sports car, big rig) x 10 series. Each has its own speed, acceleration, handling, braking and suspension, bought with coins. The four original vehicles keep their original numbers and prices. |
| Customising | Five upgrades per vehicle (engine, tyres, suspension, brakes, fuel tank; 8 levels each) and seven paint jobs. |
| Tracks | Roller-coaster terrain: long climbs and sharp plunges layered on rolling hills, with calmer stretches in between (`COASTER_AMP` in `core/terrain.ts`). Obstacle zones are set at the average height of the hills around them so the joins are never a wall. |
| Obstacles | Fixed rocks, logs, crates, barrels, boulders, ramps, broken road (gaps), seesaws, plank bridges, wrecking balls, moving platforms, mud pits, water, steep hills, cliff drops, falling rocks, rolling boulders. Hazards have a warning sign a little before them. Each is introduced at a set level, then mixed in. |
| Stunts | Seven kinds of stunt ramp (see below), real air control, front and back flips counted from the body's actual rotation, landing grades, combo multiplier, damage. From level 6 every level has a jump. |
| Brake sections | Steep descents (from level 2), jump-then-descent sequences, collapsing bridges (from level 31) and mud that bogs down a spinning wheel: holding the throttle does not finish the advanced levels. |
| Run rules | Fuel and fuel cans, coins, stars from the share of coins collected, stunt points (paid in coins), a bonus per kilometre, checkpoints (continue up to three times per run, they also repair the car), finish line. |
| Screens | Home, level select, garage, settings, driving screen with pause / restart / resume and a results panel. |

## Stunts

**Controls.** Two buttons turn the car in the air: BACK FLIP (beside the brake pedal) lifts the nose and FRONT FLIP
(beside the gas pedal) drops it. They do nothing on the ground, and the gas and brake pedals do nothing in the air. Nothing is scripted: `Vehicle.applyControls` adds spin to the real
physics body, limited per car by its moment of inertia (heavy cars turn slowly), and the world counts the
rotation the body actually made (`core/stunts.ts`). A flip takes about 40 to 60 steps of air; gravity keeps
pulling the whole time. `scripts/spin.ts` shows the spin-up of any car.

**Cars.** Torque comes from `spec.air x AIR_GAIN x agility x sqrt(jeepInertia / carInertia)`
(`data/vehicles.ts`). Buggies and sports cars turn fastest; the monster truck turns slowly, needs a long
drop for a flip and has the smallest landing window (`STUNT_STYLE`); the SUV has the widest.

**Landings.** When a car touches down after a jump it is judged 14 steps later on the angle between the car
and the slope under it, scaled by the car's stability: perfect, good, rough or crash. Only perfect and good
landings pay in full; a rough one pays 40 %, a crash nothing. Hard landings (normal speed above 11 px per
step) and rough ones add damage; the suspension goes soft as it builds up and 100 wrecks the car. A
checkpoint repairs it.

| Stunt | Points |
|---|---:|
| Front flip, back flip | 500 |
| Double flip | 1,200 |
| Triple flip | 2,200 |
| Perfect landing (after a flip or half a second of air) | +300 |
| Front flip and back flip in one chain | +1,500 once |
| Chain of stunts (each within 6 s of the last) | x1.5, x2 ... up to x4 |
| Air time over 0.8 s | up to 150 |

Points are paid in coins (10 points per coin) and shown on the driving screen: flip counters, stunt score,
multiplier, air-time readout, a landing badge and a damage bar (all quiet until the first stunt).

**Ramps** (`core/stuntshape.ts`, placed by `core/features.ts`): 1 large ramp (front flip, from level 6),
2 steep ramp (back flip, level 8), 3 double ramps (level 21), 6 uneven ramp (level 25), 4 downhill jump
(level 31), 5 mountain jump (level 35, enough air for double flips), 7 combo: back flip, a pad to brake on,
front flip (level 39). The road falls away after every lip, which is what buys the air time.

**Braking.** `steep` is a long steep descent into a valley and a steep climb out: the throttle alone arrives
too fast and takes landing damage, the brake on the way down keeps it safe, and the valley floor is where to
build speed again. From level 10 a jump, gap, bridge or mud pit is often followed straight away by one.
`scripts/gas-only.ts` plays levels with the throttle pinned: it wins none of the sampled advanced levels, the
test driver wins all of them.

## How it is organised

```
App.tsx                 shell: loads the save, shows one screen at a time with a transition
src/
  core/                 pure TypeScript, no React: runs in Node for tests and the automated driver
    terrain.ts          ground height as a function of x (original rolling hills + carved features)
    stuntshape.ts       geometry of the stunt ramps and steep descents
    stunts.ts           air time, flips, landing grade, damage, points and combos (pure maths)
    features.ts         obstacle layout generator (one Feature record per obstacle)
    vehicle.ts          chassis + two sprung wheels (ported from the Phaser game)
    world.ts            one run: physics world, chunk streaming, obstacles, pickups, rules, events
    pickups.ts  rng.ts  constants.ts
    bot.ts              automated test driver
  data/
    themes.ts           the 10 environments (palette, friction, decor, obstacle bias)
    levels.ts           the 100 level configs, generated from one formula
    vehicles.ts         the 100 vehicle specs, generated from 10 styles x 10 series; upgrades, paint
  render/               Skia drawing: scene.ts (frame), car.ts (car art), carImage.ts (car as an image for menus),
                        decor.ts (backdrops), gfx.ts
  state/                save.ts (pure save model and economy), store.ts (store, persistence, routes)
  audio/sound.ts        effects, engine loop, music
  ads/                  AdMob: config, frequency rules, banner / interstitial / rewarded, rewards (docs/ADMOB.md)
  screens/              Home, Levels, Garage, Settings, Game
  ui/                   kit.tsx (buttons, bars, screen frame), CarView.tsx
scripts/                bot.ts, diag.ts, trace.ts, gen-audio.mjs
tests/                  core.test.ts, stunts.test.ts, ads.test.ts, pacing.test.ts
```

Adding content needs no new code: a level is a row produced by `build()` in `data/levels.ts`, a vehicle is a
style x series in `data/vehicles.ts`, and an obstacle is a `Feature` type handled in three places
(`features.ts` to place it, `world.ts` for its physics, `scene.ts` to draw it).

## Performance notes

- Physics runs at a fixed 60 Hz step, at most four steps per frame, independent of the display rate.
- The game loop and drawing run outside React. A frame is recorded into one Skia picture and handed to
  the canvas through a shared value; React renders only the HUD (about eight times a second, and only
  when a number changed), the pedals and the panels.
- Terrain is streamed in 1200 px chunks. Each chunk's terrain and decoration are recorded once into a
  picture; car bodies, wheels, backdrops and liquids are cached the same way.
- Paints and rects are cached, and fixed artwork (obstacles, signs, flags, pickups, the sky) is recorded once
  into pictures and only placed each frame (`stamp()` in `render/scene.ts`), so a frame is few draw calls and
  allocates almost nothing.
- Terrain is kept from 900 px behind the car to 1500 px ahead; obstacles are created within about 1300 px
  and removed once the car is well past.

## Design decisions worth knowing

- **Nothing can trap the car.** Crates and barrels smash when hit at speed. Any loose object the car
  bulldozes or is stuck against breaks up after a moment, and fixed rocks sit lower on slopes.
- **Rockfall is fair.** A warning shows where rocks will land; only a rock still falling onto the
  driver's head ends the run.
- **Fuel cans are closer together** than in the original ten levels, because obstacles and climbs cost time.
- **Landscape only.** `app.json` asks for landscape and `App.tsx` locks it at start (Expo Go ignores `app.json`).
  Menus are laid out for a wide, short screen: level cards scroll sideways, the garage has three columns.
- **Menu pictures are images, not canvases.** Cars and the scenery behind the menus are drawn once with Skia
  into PNG data URIs (`render/carImage.ts`, `render/menuBackdrop.ts`).
- **Navigation** is a route value in the store (`state/store.ts`), not Expo Router: five screens, no deep links.

## Known limitations

- **AdMob has not run against the real SDK.** It is verified with simulated ads in the browser build only;
  see the checklist in docs/ADMOB.md for the first device build.
- **Not run on a phone or emulator.** It was verified in the browser build (same game code, Skia via
  WebAssembly), and the Android and iOS JavaScript bundles compile, but no APK was built on this machine:
  no device or emulator was available, and the drive was nearly full. Frame rate on real devices,
  touch feel, haptics and audio latency are untested.
- iOS can only be built on a Mac.
- Level difficulty is tuned against the automated driver, not human play-testing.
- The sounds are simple synthesised effects and one 17-second music loop.
